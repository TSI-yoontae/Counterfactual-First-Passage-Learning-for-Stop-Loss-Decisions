# CFPL Main Experiment Reproduction Code

This repository contains the minimal reproduction code for the main empirical results reported in the paper. 

The code is organized to produce only the final artifacts required for the default experimental specification:

```text
results/main_table.csv
results/wealth_figure.pdf
```

No intermediate raw outputs, audit files, parameter dumps, or validation-only artifacts are written to disk.

## Repository Structure

```text
code/
├── main.py
├── README.md
├── requirements.txt
├── exp/
│   ├── config.py
│   ├── experiment.py
│   └── reporting.py
├── utils/
│   ├── data.py
│   ├── features.py
│   ├── market_loader.py
│   ├── metrics.py
│   └── policies.py
├── script/
│   └── run_main.sh
└── results/
    ├── main_table.csv
    └── wealth_figure.pdf
```

The `exp/` directory contains the experiment configuration, execution logic, and reporting utilities. The `utils/` directory contains data loading, feature construction, policy evaluation, and performance metric routines. The `script/` directory provides a simple shell entry point for running the full experiment.

## Data Requirements

The reproduction requires the following four daily market-level parquet files:

```text
DE_DAX_daily.parquet
JP_Nikkei_225_daily.parquet
KR_KOSPI_200_daily.parquet
US_SP500_daily.parquet
```

By default, the code expects these files to be located in:

```text
/mnt/data
```

A different data directory can be supplied with the `--data-dir` argument.

## Installation

From the root of the `code/` directory, create and activate a virtual environment:

```bash
cd code
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

The required Python packages are listed in `requirements.txt`. At minimum, the experiment requires `numpy`, `pandas`, `pyarrow`, and `matplotlib`.

## Running the Experiment

Run the full default experiment with:

```bash
cd code
python main.py --data-dir /path/to/data
```

Alternatively, the provided shell script can be used:

```bash
cd code
bash script/run_main.sh /path/to/data
```

Before writing new outputs, the script clears the existing `results/` directory. After completion, the directory contains only:

```text
results/main_table.csv
results/wealth_figure.pdf
```

## Default Experimental Specification

The default experimental design follows the specification used for the Main Table in the paper:

```text
Holding horizon:        5 trading days
Lookback window:        60 trading days
Leverage:               1x
One-way trading cost:   5 basis points
Stop execution penalty: 10 basis points
Test period start:      2019-01-01
Stop-loss levels:       2%, 3%, 5%, 8%
Portfolio K grid:       10, 25, 50, 100, 200
```

For the DAX universe, portfolios with `K = 50`, `K = 100`, and `K = 200` are automatically excluded because the available universe contains fewer than 50 securities. The Main Table reports market-method averages over the available portfolio sizes for each market.

## Reproducibility Notes

All methods are evaluated under the same chronological training, validation, and test design. The reported performance metrics are computed from held-out test-period decisions under the default specification described above.

Utility is computed from decimal net returns using:

```text
u(n) = n - (gamma / 2) n^2
```

The reported utility is multiplied by 100 and averaged over non-overlapping test decisions and available portfolio sizes. CAGR, maximum drawdown, CVaR95, and trade rate are reported in percent. The Sharpe ratio is annualized using `252 / h` decision periods per year, where `h` is the holding horizon. Terminal wealth is computed from an initial value of one and averaged across available portfolio sizes.

CVaR95 is computed from the realized policy return series, including zero-return periods generated by no-trade decisions, and is reported as a positive loss magnitude. The trade rate is reported as the percentage of decision dates with active exposure.
